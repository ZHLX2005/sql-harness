# A03 — 审计功能(当前支持 + 扩展点)

> 何时读取:要查"sql-harness 现在能审计什么"、要用/关掉某个审计面、或要给审计体系加新能力时。
> 四个审计面各自独立,但共享一个设计观:**终端/调用方看到的是短摘要;完整记录永远落在文件里,机器可读。**

---

## 1. 全景:四个审计面

| # | 审计面 | 实现位点 | 载体 | 开关 |
| --- | --- | --- | --- | --- |
| 1 | 事件统计(cli 调用计数、doc 阅读追踪) | `analytics.py` | `$BH_SQL_HOME/analytics.json`(覆盖写,含统计聚合) | `BH_SQL_ANALYTICS=0\|off\|false\|no` 关(默认**开**) |
| 2 | 执行日志(每条命令 + 失败全 traceback) | `analytics.py:EventLog` | `$BH_SQL_HOME/sql-harness.log`(append-only NDJSON,一行一记录) | 同上(同一个总开关) |
| 3 | 长输出 spill(终端短摘要 + 文件指针) | `output.py` | `$BH_SQL_HOME/tmp/output/*.log`(保留最新 20 个) | `BH_SQL_TRACEBACK=1` 强制原始 traceback;`BH_SQL_TMP_DIR` 改 spill 目录 |
| 4 | read_only 写守卫(语句拦截) | `drivers/readonly.py` + `drivers/redis.py:_ReadOnlyRedisProxy` | 拦截即报 `ReadOnlyViolation`(错误本身也进事件日志) | 连接级 `read_only = true`(TOML 或 `add --read-only`) |

四者都跟随 `$BH_SQL_HOME`(`BH_SQL_HOME` / `BH_SQL_CONFIG_DIR` 等环境变量重定向),per-user 隔离。

---

## 2. 事件系统(analytics.py)

### 2.1 架构:observer 模式 + facade

- 业务代码只 **emit 事件**,从不碰存储。
- `EventBus.on(event, handler)` 注册 listener;listener 抛异常**永不外传**(一个坏 listener 不能弄死 CLI 或同伴)。
- 内置 listener 把标准事件写进 JSON store + NDJSON log;外部代码可挂自己的 listener(日志转发、告警)而不动 sql-harness 内部。
- 总开关关闭时 `emit()` 直接短路——不记录、不派发。
- store 路径是**零参 callable 动态解析**的(单例传 `analytics_file`),所以 `$BH_SQL_HOME` 在测试中改了也即时生效。

### 2.2 三个稳定事件(公共接口,勿随意改名)

| 事件常量 | payload | 谁在 emit |
| --- | --- | --- |
| `CLI_INVOKED` = `"cli.invoked"` | `{"subcommand": str}`(heredoc 模式 subcommand=`"heredoc"`) | `cli.main()` 每次调用;`run.py` heredoc 每次执行 |
| `DOC_READ` = `"doc.read"` | `{"doc": str, "via": str}` | `apply_skill()`(via=apply_skill)、`skill`(bare,via=skill)、`skill show`(via=skill show) |
| `COMMAND_EXECUTED` = `"command.executed"` | `{"argv": list, "code": str\|None, "ok": bool, "exit_code": int, "error": str\|None}` — argv 含子命令,heredoc 时为 `[]`;code 是 heredoc 体(CLI 模式为 None);**error 是完整 traceback**(stderr 只是压缩版,这里才是唯一完整通道) | cli 与 heredoc 的成功/失败出口各一处 |

### 2.3 analytics.json 文件形态

```json
{
  "version": 1,
  "since": "2026-..T..",
  "last_run": "2026-..T..",
  "cli": {"total_runs": 42, "by_subcommand": {"list": 7, "heredoc": 20}},
  "doc_reads": [{"doc": "x.md", "via": "apply_skill", "ts": "..."}]
}
```

`doc_reads` 上限 500 条(超限丢最旧);损坏/半写文件 → 重置为 fresh,不崩 CLI。查看:`sql-harness stats`(聚合 by_doc / by_via / recent 10 条)。

## 3. 执行日志(sql-harness.log)

- append-only **NDJSON**:每行 `{"ts": ..., "argv": [...], "code": "...", "ok": ..., "exit_code": N, "error": ...}`,`ensure_ascii=False` 保 CJK 可读。
- 记录的是**每次执行的命令全量**(CLI argv 或 heredoc 体)+ 结果,**含失败**——重启后历史仍在。
- 用途排障时:`grep` exit_code≠0 / error 非空的行;heredoc 体原文就在 `code` 字段里,可直接复跑。

---

## 4. 长输出 spill(output.py)

规则一句话:**终端拿短而忠实的摘要;长的东西写文件,给一行指针(路径/行数/大小),agent 需要时再读。**

| 机制 | 阈值/行为 |
| --- | --- |
| `spill(text, label)` | ≤ 4000 字符原样返回(逐字节不变);超过 → 写 `$BH_SQL_HOME/tmp/output/<label>-<时间戳>.log` + 返回指针行 |
| `write_spill()` | 无阈值原语;同名碰撞自动加 `-2/-3` 后缀;`SPILL_KEEP=20` 自动清最旧 |
| `render_exception()` | traceback ≤ 4000 字符且 ≤ 15 行 → 原样;否则输出摘要(headline = 驱动错误名+errno/SQLSTATE、单行 message、出错的 SQL、**用户自己代码那一帧** `file:line`)+ spill 指针。用户帧 vs 库帧的判定:`<string>` = heredoc 体 = user |
| `set_utf8_streams()` | 强制 stdin/stdout/stderr UTF-8 + `errors="replace"`——Windows 默认 cp936 会让含 CJK/特殊符号的数据在**报错过程中**二次崩溃 |

失败导向设计:spill 写盘失败(磁盘满/只读)→ 返回空指针,caller 把全文打出来而不是静默丢掉唯一副本。

## 5. read_only 写守卫(readonly.py + redis proxy)

### 5.1 双轨设计(SQL 驱动)

`install_guard(engine, hash_comments=, backslash_escapes=, extra_forbidden=, session_sql=)` 在 **engine 层**挂两个 SQLAlchemy 事件:

| 轨 | 事件 | 作用 |
| --- | --- | --- |
| 语句守卫 | `before_cursor_execute` | 检查引擎发出的**每条语句**——`conn.execute()`、`run_sql_file()`、绕过 helpers 的路径全覆盖(挂在 helpers 层就只护"礼貌路径") |
| session rail | `connect`(每个新池化连接) | 执行 `session_sql`:MySQL `SET SESSION TRANSACTION READ ONLY` / PG `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY`,**服务端**拒绝写 |

语句守卫核心 = **allow-list**(SELECT/SHOW/DESCRIBE/DESC/EXPLAIN/TABLE/VALUES/PRAGMA + 事务控制动词),未识别语句一律拒绝(deny-list 会漏 CALL/DO/LOAD DATA/HANDLER 及一切未来语句型)。检查前先 `strip_literals_and_comments()` 剥掉注释与字面量——`WHERE note='please delete'` 不算 DELETE,`-- DROP` 藏不住;MySQL 方言额外处理 `#` 注释、反斜杠转义、`/*!50000 DROP */` 可执行注释(**解开而不是删掉**);`_top_level_verb()` 处理 `WITH x AS (...) DELETE` 与 `EXPLAIN ANALYZE DELETE` 这两个"首 token 说谎"的形态。

per-driver 参数:MySQL `hash_comments=True, backslash_escapes=True` + `extra_forbidden`(INTO OUTFILE/DUMPFILE/FOR UPDATE/LOCK IN SHARE MODE);PG `extra_forbidden`(SELECT ... INTO、FOR 锁变体);SQLite 仅语句守卫(无 session rail,真边界是 URL `?mode=ro&uri=true`)。

### 5.2 Redis:_ReadOnlyRedisProxy(客户端层)

Redis 无服务端 READ ONLY 标志,所以在**客户端包一层**:`execute_command` 被代理拦截,写动词(SET/DEL/HSET/LPUSH/SADD/ZADD/EXPIRE/FLUSHDB/EVAL/…)在出进程前拒绝;读动词放行。所有路径(typed helpers、`redis_command(*args)`、`pipeline()`、`transaction()`)都汇入 `execute_command`,一处拦截全覆盖。Lua 脚本只要提到 `redis.call`/`redis.pcall` 就拒(读脚本硬要 `redis.call` → 直接 `ws.engine.eval(...)` 绕过代理);EVALSHA 走外层检查。

### 5.3 定位:护栏,不是安全边界

**两条轨都能从同一会话逃逸**(客户端是模式匹配不是解析器;`SET SESSION TRANSACTION READ WRITE` 可解开服务端轨)。唯一硬边界是**数据库账号权限**:`GRANT SELECT ON ...`。以上一切只是其上的纵深防御。SSH workspace 忽略 read_only 标志(远程 shell 不是语句流);Redis 配 ACL 用户(`+@read -@write -@dangerous`)做硬限。

## 6. 审计功能扩展点(继续优化的入口)

| 想加什么 | 怎么做 | 触碰的位点 |
| --- | --- | --- |
| **新事件类型** | `analytics.py` 事件常量区加常量 + docstring 写明 payload 契约(事件名+payload 是公共接口);业务位点 `emit(NEW_EVENT, {...})` | `analytics.py` + emitter 所在模块 |
| **自定义 listener**(转发/告警/采样) | `from sql_harness.analytics import on, CLI_INVOKED, ...` 然后 `on(EVENT, handler)`;handler 拿 payload dict,异常自动吞。可挂在外部进程内(heredoc 里也可挂) | 不改 sql-harness 内部 |
| **新子命令的统计** | 无需做任何事——`CLI_INVOKED` 自动带 subcommand,`stats` 的 by_subcommand 自动收录 | 零改动 |
| **执行日志加字段** | `EventLog.append` 的 record 由 emit 方构造,改两处 emit 的 payload;注意 NDJSON 消费者兼容(version 字段在 json store 侧) | `cli.py` / `run.py` 的 emit 调用 |
| ** spill 阈值调整** | `output.py` 顶部三个常量:`SPILL_THRESHOLD`/`SPILL_MAX_LINES`/`SPILL_KEEP` | `output.py` |
| **新驱动接 read_only** | 仿照 mysql.py:`install_guard(engine, hash_comments=?, extra_forbidden=?, session_sql=?)`;无 session 级机制的后端传 `session_sql=None`(学 sqlite);非语句型协议学 redis.py 写 proxy | `drivers/<name>.py` |
| **stats 输出新维度** | `AnalyticsStore.stats()` 加聚合;注意它读的是 store 内存结构,新维度要有对应的 record_* 累积 | `analytics.py` |
| **审计数据外置**(SQLite/远端) | 实现一个新 listener 注册到 bus,替代/并行于内置 store listener;`Analytics` 构造已把 store 与 bus 解耦 | `analytics.py` facade 区 |

扩展纪律:

1. 事件名与 payload 形状是**稳定契约**——改之前全局 grep emitter/listener。
2. listener 永不抛异常出界;存储失败降级为"丢记录"而不是"崩 CLI"(analytics.json 损坏 → 重置,spill 失败 → 空指针)。
3. 新审计面默认跟随 `BH_SQL_ANALYTICS` 总开关语义(默认开,值 `0|off|false|no` 关)或自建 env 开关时沿用 `_OFF_VALUES` 风格。
4. Windows 全程注意 UTF-8(`ensure_ascii=False` 写文件 + `set_utf8_streams()` 已兜底,新输出路径别自己开 GBK 口子)。
