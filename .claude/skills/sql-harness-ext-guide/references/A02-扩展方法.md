# A02 — 扩展方法

> 何时读取:要给 sql-harness 加任何东西时——新 driver、新 helper、新 CLI 子命令、新 interaction-skill、新 meta skill——或要构建/发布 wheel 时。
> 文件归属问题(放哪)先看 [[A01-项目介绍与目录规范]] §3;本 ref 解决"怎么加"。

## 1. 加一种连接适配器(driver)

**一句话定义**:一个 driver = 把一种**协议**(SQL / SSH / Redis / HTTP / 自定义)封装为 `Workspace`,让 `use_workspace(name)` 对它生效。实现位点 `src/sql_harness/drivers/<name>.py`,注册位点 `drivers/__init__.py:get_driver()`。

### 5 阶段流水线

| 阶段 | 动作 | 产出 |
| --- | --- | --- |
| 0. 定类型 | DB(SQLAlchemy)?shell?K/V?HTTP? | 类别 + 依赖 |
| 1. 实现 driver | `drivers/<name>.py` 满足 `Driver` Protocol + 注册 | Driver 对象 |
| 2. 加 zone 助手 | `helpers.py` 暴露面向 agent 的动词 | 5–10 个自动注入函数 |
| 3. CLI 子命令(如需) | `cli.py` 注册 `cmd_<name>` + parser | 可独立调用的命令 |
| 4. 文档 + 测试 | mechanic + strategy 文档;单测 + 集成测试 | 通过审查的工作流 |

> SQL 类(复用 SQLAlchemy)只需 1+4;非 SQL 后端(模仿 ssh.py / redis.py)需要 1+2+3+4。

### 阶段 1:实现 `Driver` Protocol

```python
# src/sql_harness/drivers/<name>.py
class Driver(Protocol):          # 定义在 drivers/__init__.py
    name: str
    def make_engine(self, url, pool, password=None, read_only=False): ...  # 返回"engine"(非 SQL 是原生 handle)
    def list_tables(self, engine, schema=None) -> list[str]: ...           # 非 SQL:raise NotImplementedError
    def describe(self, engine, table, schema=None) -> list[dict]: ...      # 非 SQL:raise NotImplementedError
    def quote_ident(self, ident) -> str: ...
```

`make_engine` 返回什么:

| 类型 | 返回 | agent 用法 |
| --- | --- | --- |
| SQL DB | `sqlalchemy.Engine`(建议走 `install_guard()` 若支持 read_only) | `query/execute/with_transaction` |
| shell / HTTP | 自定义 handle(`.client/.sftp/.exec`…) | `ssh_exec` 等 typed helpers |
| K/V | 自定义 handle | 自定义 `redis_*` 式 helpers |

注册到 `drivers/__init__.py`:

```python
if name == "<name>":
    from .<name> import XDriver
    return XDriver()
```

依赖:`uv add "<pkg>>=<ver>,<next-major>"` 并进 pyproject `[project.dependencies]`。

### 阶段 2:加 zone 助手(helpers.py)

命名:`<verb>_*` 模式(`ssh_exec/ssh_upload`;`redis_get/redis_eval`)。每个 helper 必须:

1. 经 `current_workspace()` 取活动 workspace;
2. 验证驱动类型(不匹配 → `RuntimeError("... is a postgres workspace, not ssh")`——参考 `_ssh_handle()` / `_redis_handle()` 私有卫兵);
3. 调用 `ws.engine.<verb>(...)` 或原生 handle;
4. **返回纯数据**(dict / list[dict] / None),永不返回内部对象。

```python
def ssh_exec(command: str, timeout: float = 30.0) -> dict:
    handle = _ssh_handle()              # 驱动校验 + 取 handle
    result = handle.exec(command, timeout=timeout)
    return result.to_dict()             # dict, not CommandResult
```

### 阶段 3:CLI 子命令(仅当 agent 之外也要用时)

```python
# _build_parser() 里:
p_x = sub.add_parser("<name>", help="...")
p_x.add_argument("-c", "--connection")
x_sub = p_x.add_subparsers(dest="<name>_cmd")

# commands dict 里:
"<name>": cmd_x,
```

约定:`sub=` 缺失 → exit 2 + stderr;退出码**透传**底层命令的;stdout = 命令输出,stderr = harness 自身错误;info 类命令输出 JSON。zone-scoped 子命令记得走 `_require_connection_or_fail(args)` + `_activate_ssh_zone()` 式激活。

### 阶段 4:文档 + 测试

| 层 | 位点 | 内容 |
| --- | --- | --- |
| mechanic | `interaction-skills/<driver>/<name>.md` | Detection/Approach/Gotchas + CLI 等价物 |
| strategy | `agent-workspace/zones/meta/skills/<name>.md`(确属跨 DSN 时) | 何时用、选型、安全 |
| README | 根 `README.md` 驱动表加一行 | `✅` 状态 |
| SKILL.md | 根 SKILL.md Drivers 节 + helper 清单 | 改完 `uv build` |
| 单测 | `tests/unit/test_<name>.py` | URL 解析(parametrize 5+ 形式)+ helper 防护(错驱动 → RuntimeError) |
| 集成 | `tests/integration/test_<name>.py` | `pytestmark = skipif(not os.environ.get("BH_<NAME>_URL"))` env-gated,别硬连真实主机 |

### driver 易错表(SSH 适配器复盘)

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 假设 `ws.engine` 是 `isinstance(Engine)` | 非 SQL workspace type error | duck-type;DB 是 connect,SSH/Redis 是原生方法 |
| 非 SQL 类实现 `list_tables/describe` 返回空 | agent 困惑 | `raise NotImplementedError("... use ssh_exec()")` |
| 子命令缺 sub 时 exit 0 | agent 误以为成功 | exit 2 + stderr |
| 退出码被吞(return 0) | CI 误判 | 透传 exit_code |
| helper 返回内部对象 | 序列化失败 | 只返回纯数据 |
| 集成测试硬连真实主机 | CI 不可用 | env-gated |

## 2. 加一个 interaction-skill(mechanic)

1. 定位子层(判定标准见 [[A01-项目介绍与目录规范]] §2.3):跨 SQL → `shared/sql/`;某驱动专属 → `<driver>/`;工具层 → 顶层。
2. 套三段骨架:**Detection / Approach / Gotchas**,开头 1–2 句说明这是什么、什么时候用。
3. 硬约束:25–110 行;代码块只用已注入 helper(`use_workspace/query/execute/...`),**不 import**;跨 SQL 通论开头写明"适用 postgres/mysql/sqlite;redis/ssh 不适用"。
4. 文件名 kebab-case,先查是否撞已有概念(`migrations.md` 撞名事故 → PG 数据迁移改名 `pg-data-movement.md`)。
5. 超过 110 行 → 拆成两个聚焦文件(如 `joins.md` + `joins-advanced.md`)。
6. 无需改 pyproject——`interaction-skills/` 整树自动 force-include 进 wheel;但根 SKILL.md 的 Interaction Skills 索引要加一行,**改完 `uv build`**。

## 3. 加一个 meta strategy skill(zones/meta/skills/)

1. 确认它真是**跨 DSN strategy**(何时调 pool_size、何时隔离 workspace),不是 mechanic——mechanic 走 §2。
2. 一个文件一个主题(`pool.md`、`workspace.md`),内容聚焦菜谱 + 默认值表 + "何时 tune"。
3. 该目录会被 force-include 打进 wheel——**确认目录里没有临时/测试文件**再 build(0.3.6 曾差点把 `zz_*.md` 发出去)。
4. **重跑 `sql-harness init`** 把新 skill 安装到运行时 `$BH_SQL_HOME/.../zones/meta/skills/`,否则 `apply_skill()` 找不到。
5. meta skill 不会自动浮现(`use_workspace` 的 zone_skills 列表不含它),它是被动回退——在合适的 interaction-skill 或 SKILL.md 里提一句它的存在,agent 才会 `apply_skill("pool")`。

## 4. 加一个 heredoc helper

两层注入链,按作用域选:

| 作用域 | 位点 | 加载时机 |
| --- | --- | --- |
| 全局共享(所有连接可用) | `src/sql_harness/helpers.py` | `run.py` 启动时全量并入 exec globals |
| 用户自定义(不改源码) | `$BH_SQL_AGENT_WORKSPACE/agent_helpers.py`(`agent_loader.py` 加载) | 启动时,预种子核心 helpers,公开名并入 |
| 某连接专属 | `agent-workspace/zones/<conn>/helpers.py`(`helpers.py:_load_zone_helpers`) | `use_workspace()` 时并入,**覆盖共享基座** |

写共享 helper 的规则同 §1 阶段 2(纯数据返回、驱动校验、经 `current_workspace()`);写完在根 SKILL.md 的 helper 表里登记 + 重 build。

## 5. 加一个 CLI 子命令

1. `cli.py:_build_parser()` 加 parser + 参数。
2. 写 `cmd_<name>(args, harness) -> int` 顶部小节(`# --- Subcommand implementations ---`)。
3. `main()` 的 `commands` dict 登记映射。
4. 遵循现有约定:`_emit()` 输出 JSON;长输出交给 `output.spill()`;退出码语义化(2 = 用法错);zone-scoped 命令需要 `-c/--connection` 或 `$BH_SQL_ACTIVE_CONNECTION`。
5. 测试:`tests/unit/test_cli.py` 加用例(现有 500+ 行可参考其 fixture 风格);根 SKILL.md "Other subcommands" 行更新 + 重 build。

## 6. 改前端(`web/` → `_web_assets/`)

所有 React/Vite/TypeScript 工具链都在 **`web/`** 子目录,**根目录不污染**(不要把 package.json / vite.config.ts / node_modules 放仓库根)。React 重写于 2026-09 完成,把旧的 vanilla `_web/` 三件套删除。

### 6.1 SOP:加新组件 / 改样式 / 调逻辑

```bash
cd web
npm ci                       # 装依赖(锁文件 package-lock.json 已入库)
npm run dev                  # Vite dev server on :5173,代理 /api/* 到 :8765
# 同时在另一个终端:
PYTHONPATH=src uv run sql-harness web --port 8765 --no-open
# 浏览器打开 http://127.0.0.1:5173 调试
npm run build                # tsc --noEmit + vite build,产物写到 ../src/sql_harness/_web_assets/
PYTHONPATH=src uv run pytest tests/unit -q    # 后端测试不受前端改动影响
```

### 6.2 改动落在哪里

| 你要加的 | 放哪 |
| --- | --- |
| 新 React 组件 | `web/src/components/<Name>.tsx`,由 `App.tsx` 引入 |
| API wrapper / 类型 | `web/src/lib/api.ts`(types 同文件) |
| 全局状态 | `web/src/lib/state.tsx`(`useReducer` + Context) |
| 全局 CSS / 主题 | `web/src/styles/globals.css` |
| 后端白名单放宽 | `src/sql_harness/webapp.py::_serve_asset` 的 `_HASSHED_RE` 或新分支;测试同步 |

### 6.3 端到端循环 vs 单文件构建

开发期间 `npm run dev` 走 Vite HMR,改 `.tsx` / `.css` 即时刷新,**不重 build**。改 `web/vite.config.ts` 或 `web/index.html` 必须重启 dev server。**发布前必须 `npm run build`**——`src/sql_harness/_web_assets/` 是 force-include 进 wheel 的源,如果 build 没跑,wheel 里仍是旧产物。

### 6.4 路径与白名单契约

Vite 把产物写到 `src/sql_harness/_web_assets/`,产物文件名是 `index.html` + hashed `index-<hash>.js` / `index-*.css` + lazy `Editor-*.js`。webapp 的 `_serve_asset` 白名单:

- `index.html`(精确,`Cache-Control: no-store`)
- 任何 `<name>-<hash>.<ext>` 形式的顶层 hashed chunk(`Cache-Control: max-age=31536000, immutable`)
- 其他全部 404(防路径穿越)

改 webapp.py 时确保 `_HASSHED_RE` 与 Vite 的 chunk 命名格式一致(默认 `[A-Za-z0-9_-]{8,}`)。改 Vite 的 `build.rollupOptions.output.chunkFileNames` 时同步这个正则。

## 7. 构建与发布(uv build → PyPI)

### `_skills/` 与 `_web_assets/` 都是生成物

`uv build` 时 pyproject `[tool.hatch.build.targets.wheel.force-include]` 映射:

| 仓库源 | wheel 内路径 |
| --- | --- |
| `SKILL.md` | `sql_harness/_skills/SKILL.md` |
| `interaction-skills/`(整树) | `sql_harness/_skills/interaction-skills/` |
| `agent-workspace/zones/meta/skills/` | `sql_harness/_skills/zones-meta-skills/` |
| `src/sql_harness/_web_assets/index.html` | `sql_harness/_web_assets/index.html` |
| `src/sql_harness/_web_assets/assets/` | `sql_harness/_web_assets/assets/` |

关键约束:

- **根 SKILL.md 是唯一事实源**,不手写任何副本。改了必须 `uv build`;agent 注册副本用 `sql-harness skill install`(`--target` / `--codex`)刷新。
- `sql-harness skill`(bare)读 wheel 内 `_skills/SKILL.md`;源码 checkout 无 `_skills/` 时回退根 SKILL.md。
- `skill install` 需要**真实 wheel 安装**才工作;源码 checkout 里 `_bundled_skills_root()` 返回 None → exit 2。
- **`_web_assets/` 由 `cd web && npm ci && npm run build` 产出**;`uv build` 之前必须有该产物(否则 hatchling 会报 "Forced include not found")。改前端不要忘了 build。
- `markdown-it-py` 已从依赖删除(PR2 of React rewrite)——客户端用 react-markdown + remark-gfm 渲染。

### 发布流程速记

```bash
# 0. (若改过前端) 重新构建 SPA
cd web && npm ci && npm run build && cd ..
# 1. bump pyproject.toml version
# 2. 干净构建 + 本地验证
rm -rf dist && uv build
uv tool install dist/sql_harness-<ver>-py3-none-any.whl && sql-harness --help && uv tool uninstall sql-harness
# 3. 上传(token 走 UV_PUBLISH_TOKEN env,绝不进命令行/history)
uv publish
# 4. 验证 + tag
sleep 10 && curl -s https://pypi.org/pypi/sql-harness/json | python -m json.tool | head
git tag v<ver> && git push origin v<ver>
```

发布前必查:

- [ ] `cd web && npm ci && npm run build`(若改过前端)
- [ ] `unzip -l dist/*.whl` 无临时文件(`zz_*`、`nope.md`),且含 `_web_assets/index.html` 与 `_web_assets/assets/*.js|*.css`
- [ ] `uv run pytest tests/unit -q` 通过(Windows webapp keep-alive 抖动重跑即可)
- [ ] wheel 里 `interaction-skills/` 树结构与仓库一致

### CI

tag 推送触发 PyPI publish workflow(`.github/workflows/`);smoke test 断言 helpers 注入而非 DB 调用。改动 CI 前先看现有 workflow 的触发条件。
