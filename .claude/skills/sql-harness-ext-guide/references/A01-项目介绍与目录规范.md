# A01 — 项目介绍与目录规范

> 何时读取:认识 sql-harness、判断"这个文件该放哪"、查某个目录的家规、或要动文档结构之前。
> 原则:**每个目录一种家规。先定位目录,再套模板。**

---

## 1. 项目是什么

sql-harness 是一个**单进程、无 daemon** 的 SQL + Redis + SSH CLI,面向 LLM agent(不是人):heredoc 脚本 + 自动注入 helpers,连接配置集中在一个明文 TOML 文件。

| 维度 | 事实 |
| --- | --- |
| 语言/运行时 | Python ≥ 3.12,hatchling 构建,uv 管理 |
| 包名/命令 | `sql-harness`(console script → `sql_harness.run:main`) |
| 驱动 | postgres(psycopg3)/ mysql(PyMySQL)/ sqlite(stdlib)/ redis(redis-py)/ ssh(paramiko),5 驱动共享一个 heredoc 命名空间 |
| 体量 | `src/sql_harness/` 约 5.6k 行(含 webapp),单测 2.7k 行 |
| 状态目录 | `$BH_SQL_HOME`(默认 `~/.config/sql-harness/`):connections.toml + agent-workspace/ + analytics.json + sql-harness.log |
| 分发 | PyPI wheel;SKILL.md + interaction-skills/ + meta skills 经 pyproject `force-include` 打进 wheel,`sql-harness skill install` 物化到 agent 的 skills 目录 |
| 姊妹项目 | browser-harness(CDP 浏览器版)——结构刻意同构:run.py heredoc 入口、agent-workspace、zone 隔离、skill 分发链 |
| Code priorities | Clarity → Precision → Low verbosity → Versatility;Contributing 一句话:**Consider what is really needed. Prefer the smallest diff.** |

架构一句话:**一连接一 workspace,engines 活在 `SqlHarness` 进程内注册表;SQL 驱动走 SQLAlchemy Engine,Redis/SSH 走 native-handle 模式(typed helpers 构成 heredoc 面,`query()` 等直接 raise `NotImplementedError`)。**

## 2. 目录地图与家规

### 2.1 仓库根 — 只有两个文档 + 一个脚本 + 一个构建配置

| 文件 | 家规 |
| --- | --- |
| `SKILL.md` | **agent 日常入口,唯一事实源**。必须有 frontmatter(`name: sql-harness` + 触发式 description,不是内容总结)。固定小节顺序:Usage → Drivers & capabilities → Generic SQL helpers → Interaction Skills → Cross-DSN strategy skills → What actually works → Design Constraints → Gotchas → Read-only → Domain/table skills。改了它 → 必须 `uv build`(见 [[A02-扩展方法]] §7) |
| `README.md` | **PyPI 主页,唯一人类文档**。一句 pitch → Quickstart → 架构表 → 驱动表。**不写触发词**(那是 SKILL.md 的事),**不进 wheel**(force-include 刻意排除) |
| `sql-harness`(无扩展名) | dev launcher:优先 repo `.venv` → `uv run` → `PYTHONPATH=src` 回退;自动 `export BH_SQL_HOME="$ROOT/.sql-harness-dev"` 隔离 dev 状态 |
| `pyproject.toml` | 依赖、scripts、pytest 配置、`force-include`(wheel 文档与 SPA 打包的唯一声明处):四组——`SKILL.md`、`interaction-skills/`、`agent-workspace/zones/meta/skills/`、`_web_assets/`(Vite 产物) |

**❌ 根级不建的文件**(2026-09 精简决策,勿重建):`AGENTS.md`、`docs/`、`PROJECT_INDEX.md/.json`、`.claude-plugin/`。开发建设知识的唯一归档地 = 本 skill 的 references/。

### 2.2 `src/sql_harness/` — 受保护核心包(~5.6k 行)

模块职责速览(改模块结构时同步本表,并同步 [[A02-扩展方法]]):

| 模块 | 职责 | 关键点 |
| --- | --- | --- |
| `run.py` | 入口分流 | 非 TTY stdin + 无参数 → heredoc exec;否则转 cli.main()。helpers 全量并入本模块 globals |
| `cli.py` | argparse 子命令(~1.2k 行) | `cmd_*` 函数 + `_build_parser()` + `commands` dict;加子命令见 [[A02-扩展方法]] §5 |
| `config.py` | TOML schema | `ConnectionConfig`/`PoolConfig`/`ConnectionsConfig`;`${env:VAR}` 展开;密码打码;手写 TOML writer(save) |
| `paths.py` | 状态目录解析 | `BH_SQL_HOME` 一级覆盖 → `XDG_CONFIG_HOME` → `~/.config`;zone 名校验防路径穿越 |
| `manager.py` | `SqlHarness` 注册表 | 一连接一 workspace;engine 懒打开、进程内缓存;`apply_skill()` 走 zone skills |
| `helpers.py` | heredoc 注入助手(~1k 行) | 全部返回纯数据;SQL 通用 + PG 专属 8 个 + ssh_* 6 个 + redis_* 14 个;zone helpers 可覆盖 |
| `agent_loader.py` | 加载 `agent_helpers.py` | 公开名合并进 heredoc 命名空间,模块预种子核心 helpers |
| `analytics.py` | 事件总线 + 统计 | observer 模式;3 个稳定事件;详见 [[A03-审计功能]] |
| `output.py` | 终端输出策略 | UTF-8 强制;长输出 spill 到 `$BH_SQL_HOME/tmp/output/`;异常摘要渲染 |
| `webapp.py` | `sql-harness web` 本地文档站(~1.3k 行) | loopback only;`resolve_doc()`/`resolve_create()`/`resolve_rename_target()` 是写边界——改路径处理前先读 docstring。Host/Origin/PUT+JSON 三重守卫;静态资源通过 `importlib.resources` 读 `sql_harness/_web_assets/` |
| `drivers/` | 后端适配层 | `Driver` Protocol:`make_engine` / `list_tables` / `describe` / `quote_ident`;`get_driver()` 按名查找 |
| `drivers/readonly.py` | SQL 只读守卫 | 语句 allow-list + session rail 双轨;详见 [[A03-审计功能]] |
| `_web_assets/` | **Vite 产物**(由 `web/` 构建) | React SPA: `index.html` + hashed `index-*.js`/`index-*.css` + lazy `Editor-*.js`;不手工编辑。`/api/doc` 的 `html` 字段在 PR2 重写后被去除,markdown 由客户端 react-markdown 渲染 |
| `_web/` | **已删除(React 重写后)** | 旧 vanilla JS 三件;`_serve_asset` 的 fallback 分支一并删除 |
| `_skills/` | **构建产物,wheel 内文档包** | 源码树不存在;`uv build` 时 force-include 生成 |

### 2.3 `interaction-skills/` — mechanic 卡点文档(agent 在卡住时读)

家规(每个文件都遵守):

- 纯 markdown,**一个文件一个 mechanic**,文件名 = 主题 kebab-case。
- 固定骨架(terse):
  ```
  # <Mechanic 名>
  <1-2 句>这是什么 / 什么时候用。
  ## Detection   ← 怎么判断要用它
  ## Approach    ← 怎么做(```python 块,只用已注入 helper,不 import)
  ## Gotchas     ← 会踩的坑
  ```
- 长度 **25–110 行**,超过就拆两个文件。
- 代码块只用已注入的 helper(`use_workspace/query/execute/with_transaction/...`),**不要 `import`**。
- 跨 SQL 通论开头写明"适用 postgres/mysql/sqlite;redis/ssh 不适用"。

子层判定(v0.3.6 起):

| 子层 | 内容 | 判定标准 |
| --- | --- | --- |
| `shared/sql/` | 跨 SQL 驱动通论(16 个:transactions、pooling、joins(+adv)、aggregations(+adv)、window-functions(+adv)、recursive-ctes(+adv)、migrations、indexes-and-explain、schema-introspection、encoding-and-charset、large-result-sets、timeouts-and-cancellation) | 多数 SQL 驱动通用 |
| 顶层 `*.md` | 工具层机制(2 个:save-run-cycle、zone-skill-auto-surface) | 与驱动无关 |
| `postgres/` | PG 专属深度(7 个:plan-reading、btree-indexes、specialized-indexes、table-optimization、slow-queries-joins、json-columns、pg-data-movement) | PG 独有/行为差异大 |
| `mysql/` | MySQL 专属(json-columns) | 同上 |
| `ssh/` | SSH 专属(3 个:ssh、auth-and-tunnels、docker-via-ssh) | 非 SQL 后端 |
| `redis/` | Redis 专属(4 个:redis、lua、keyspace、types) | 非 SQL 后端 |

**不允许其他子层**;不要建 `interaction-skills/references/`。

### 2.4 `agent-workspace/` — agent 唯一可写区

```
agent-workspace/
├── agent_helpers.py            # 共享基础 helpers,每次运行自动并入(示例文件入库,运行时在 $BH_SQL_HOME)
├── zones/
│   ├── example_pg/             # 示例 zone:scripts/ + skills/
│   └── meta/skills/            # 跨 DSN strategy(pool.md、workspace.md)——会被打进 wheel!
```

- `zones/<conn>/skills/<name>.md`:该 DSN 专属知识(schema、怪表、慢查询模式),`apply_skill(name)` 在该 zone 命中。
- `zones/meta/skills/<name>.md`:跨 DSN strategy 菜谱,任何 zone 找不到时的**被动回退**;`sql-harness init` 安装到运行时;**整目录 force-include 进 wheel——别放临时/测试文件**。
- 新增 meta skill 后要**重跑 `sql-harness init`**,否则运行时 `apply_skill` 找不到。
- 运行时数据(analytics.json、sql-harness.log、tmp/output/)在 `$BH_SQL_HOME/`,**不在仓库**,别给它们建仓库文档。

### 2.5 `tests/` — 单测 + 集成分层

- `tests/unit/` — 无网络依赖,`pytest tests/unit -q` 是发布门槛。
- `tests/integration/` — 需要真实 PG/MySQL/SSH(test_pgexercises_practice、test_pg_optimization 等),本地手动跑。
- 已知抖动:`tests/unit/test_webapp.py` 的 HTTP 测试在 Windows 偶发 `ConnectionAbortedError [WinError 10053]`(keep-alive 竞态),重跑即可,**不要为此改产品代码**。

### 2.6 其他

- `dist/` — 构建产物(gitignore);`.github/` — CI + issue 模板;`interaction-skills/` 与根 SKILL.md 经 force-include 进 wheel(见 §2.3/§2.1)。

## 3. 速查:我要加 X,放哪个目录?

| 你要写的东西 | 放这里 | 受众 |
| --- | --- | --- |
| 改 agent 日常用法(触发词/约束) | 根 `SKILL.md`(唯一事实源,改完重 build) | agent |
| 用户可见的介绍/Quickstart | 根 `README.md`(PyPI 页,不进 wheel) | 人类 |
| **开发建设知识**(模块/构建/架构决策) | **本 skill 的 references/**(仓库内不放) | 开发者 |
| 跨 SQL mechanic 卡点 | `interaction-skills/shared/sql/<topic>.md` | agent |
| 某驱动专属 mechanic | `interaction-skills/<driver>/<topic>.md` | agent |
| 工具层机制(与驱动无关) | `interaction-skills/<topic>.md`(顶层) | agent |
| 通用 strategy 菜谱(池/工作区隔离) | `agent-workspace/zones/meta/skills/`(重跑 init) | agent(apply_skill 读) |
| 某 DSN 专属知识 | `agent-workspace/zones/<conn>/skills/`(运行时,不入库) | agent |
| 新后端适配 | `src/sql_harness/drivers/<name>.py`(SOP 见 [[A02-扩展方法]] §1) | 代码 |
| 审计/日志相关 | `src/sql_harness/analytics.py` / `output.py`(见 [[A03-审计功能]]) | 代码 |
| ~~docs/、AGENTS.md、PROJECT_INDEX~~ | **已删除,勿重建** | — |
| ~~运行时数据文档~~ | 在 `$BH_SQL_HOME/`,不在仓库 | — |

> 口诀:**仓库根只有 SKILL.md(agent 入口)+ README.md(PyPI 主页);mechanic 在 interaction-skills/;strategy 在 zones/{meta,<conn>}/skills;开发知识在本 skill references/。**

### 双轴判定(放错目录前先过这两问)

| 轴 | 选项 | 怎么判断 |
| --- | --- | --- |
| 内容 | mechanic(怎么写)vs strategy(什么时候选) | 卡住查 mechanic;决策查 strategy |
| 加载 | SKILL.md 喂给 host agent(主动读)vs `apply_skill()` runtime 调用 | 看 force-include 路径:进 `interaction-skills/` = 前者;进 `zones/*/skills/` = 后者 |

典型混错:把 mechanic 写进 `zones/meta/skills/`(agent 永远不会 apply_skill 它);把 strategy 写进 `interaction-skills/` 索引(mechanic 文档膨胀)。
